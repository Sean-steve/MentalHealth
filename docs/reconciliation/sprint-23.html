Sprint 23 reconciliation

PARTIAL — CLINICAL GOVERNANCE FIXES REQUIRED

Reusable implementation

  • mindos/clinical_record/ implements longitudinal record, provenance-aware timeline, observations and access-aware projections.
  • mindos/outcomes/ implements measure registry, measurement validation, comparability, series, baselines, trend evaluation, reviews, immutable snapshots, alerts, adapters and reconciliation.
  • Canonical Sprint-23 state-machine values, events and error classes are already registered.

Critical corrections

  • The trend layer currently hard-codes clinical-change thresholds and describes them as canonical. Those values must come from approved Clinical Governance artifacts; missing policy must produce UNKNOWN/REVIEW_REQUIRED, not guessed thresholds.
  • The trend engine contains fallback MCID/target values. Clinical interpretation must fail safely when no governed rule exists.
  • Two Outcome services currently pass AUTHZ_RELATIONSHIP_REQUIRED into an AuthorizationError type that only accepts legacy AUTHZ_001–004 values.
  • Outcome event/audit payloads should be minimized; raw clinical values do not belong in general-purpose event or audit metadata when references are sufficient.
  • No Sprint-23 database migration, API/server wiring or canonical Sprint-23 acceptance suite exists in the uploaded snapshot.

Reconciliation decision

Keep the longitudinal/outcome architecture, remove invented clinical defaults, make clinical-change rules governance-supplied, fix authorization typing, minimize event/audit payloads, add persistence/API/tests, and only then accept Sprint 23.
